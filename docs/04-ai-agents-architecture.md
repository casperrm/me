# الجزء الرابع: بنية الذكاء الاصطناعي والوكلاء الأذكياء

الهدف من هالجزء: نظام ذكاء اصطناعي **منظّم وقابل للتوسع**، مو "شات بوت" واحد بيحاول يجاوب عن كل شي. كل Agent إله دور محدد، حدود واضحة، وطريقة موحدة للتفكير والتواصل ومشاركة الذاكرة.

## الفلسفة: لماذا Agents متعددين مو Agent واحد ضخم

Agent واحد "يعرف كل شي" بيصير صعب التحكم فيه، صعب الاختبار، وصعب محاسبته على قرار معيّن. بدل هيك، Cedar Point OS مبني على **فريق من الوكلاء المتخصصين**، كل واحد إله خبرة (domain) محددة، وبينسقوا ببعض عبر طبقة تنسيق مركزية. هاد نفس المنطق اللي وكالة حقيقية بتشتغل فيه: ما في موظف واحد بيسوي التصميم والمالية والاستراتيجية — كل واحد إله تخصص، وفي مدير بينسق بينهم.

## الأدوار

### AI Orchestrator (المنسّق)
**الدور:** نقطة الدخول لأي طلب — من المستخدم مباشرة، أو من workflow آلي، أو من حدث بالنظام. مسؤوليته:
1. فهم الطلب وتفكيكه لمهام فرعية.
2. تحديد أي Agent (أو مجموعة Agents) المسؤول عن كل مهمة فرعية.
3. تمرير السياق اللازم لكل Agent (من الـ Knowledge Graph — الجزء الخامس).
4. تجميع المخرجات من عدة Agents لو الطلب يتطلب أكتر من تخصص (مثلاً: "جهزلي خطة حملة كاملة" بيحتاج Marketing Strategist + Design + Finance مع بعض).
5. تمرير الناتج النهائي لـ AI Supervisor قبل ما يوصل للمستخدم أو ينفذ.

**ما بيسويه:** ما بينتج محتوى بنفسه، وما بيتخذ قرار نيابة عن Agent متخصص — دوره تنسيق وتوجيه بس.

### AI Supervisor (المشرف)
**الدور:** طبقة مراجعة الجودة قبل ما أي مخرج AI يوصل للإنسان أو يُنفذ تلقائياً:
- التحقق من الالتزام بـ Brand Guidelines (موديول العلامة التجارية).
- التحقق من عدم وجود تعارض مع سياسات الوكالة أو بيانات خاطئة (hallucination check بمقارنة مع الـ Knowledge Graph).
- تصنيف القرار: هل هو **إجراء آمن** (ينفذ مباشرة) أو **قرار حرج** (لازم يوقف عند بوابة الموافقة البشرية)؟

**قاعدة التصنيف:**
| نوع الإجراء | مثال | المسار |
|---|---|---|
| آمن — تنفيذ مباشر | توليد مسودة تصميم، اقتراح جدول محتوى، تلخيص تقرير | ينفذ، ويُسجّل بالـ Activity Feed |
| حرج — يتطلب موافقة | إرسال فاتورة، نشر محتوى للعميل، توقيع/تعديل عقد، تعديل ميزانية | يتوقف عند بوابة الموافقة (موديول المشاريع/المالية/العقود) |

### الوكلاء المتخصصون (Specialist Agents)

**Marketing Strategist Agent**
- يقترح استراتيجيات حملات، مواضيع محتوى، تقسيم جمهور (targeting).
- يقرأ من: تاريخ العميل، أداء الحملات السابقة (Analytics)، Knowledge Base.
- يكتب إلى: `CampaignBrief`, `ContentCalendar` (موديول الحملات).

**Design Agent**
- ينتج/يقترح تصاميم عبر Design Studio.
- ملزم بقراءة `BrandGuideline` و`BrandConstraint` قبل أي توليد.
- يكتب إلى: `StudioAsset` (موديول AI Studios).

**Video Agent**
- ينتج/يقترح محتوى فيديو عبر Video Studio، بنفس قيود العلامة التجارية.
- يتعاون مع Design Agent لما الفيديو يحتاج عناصر بصرية مشتركة.

**Finance Agent**
- يراقب الميزانيات والربحية لحظياً (موديول المالية).
- ينبّه لما مشروع يقترب من تجاوز الميزانية، أو لما هامش الربح ينخفض عن حد معيّن.
- أي إجراء مالي فعلي (فاتورة، تعديل سعر) = قرار حرج، دايماً يمر ببوابة الموافقة.

**Research Agent**
- يجمع ويحلل بيانات سوق، منافسين، اتجاهات (trends) — من مصادر داخلية (Knowledge Base) وخارجية (عبر Integrations Hub).
- يغذّي Marketing Strategist Agent وProduct Manager Agent بالرؤى.

**Product Manager Agent**
- يراقب استخدام النظام نفسه وأداء الموديولات (عبر Analytics)، ويقترح تحسينات على سير العمل الداخلي للوكالة (مو على منتج المنصة — على كيفية استخدام الوكالة للمنصة).
- نقطة الربط بين ملاحظات الفريق (Collaboration) والأتمتة (Automation Engine) — بيقترح workflows جديدة بناءً على أنماط عمل متكررة.

> **قابلية التوسع:** أي Agent جديد بالمستقبل (مثلاً SEO Agent أو Social Listening Agent) لازم يتبع نفس النمط: مصادر قراءة واضحة، وجهات كتابة واضحة، وتصنيف واضح لأي إجراء "آمن" مقابل "حرج".

## كيف الـ AI بيفكر: دورة المهمة (Task Lifecycle)

1. **الاستقبال (Intake):** طلب بيوصل (من إنسان عبر AI Command Center، أو من Automation trigger).
2. **الفهم والتفكيك (Understanding):** AI Orchestrator يحلل الطلب ويحدد الـ Agent(s) المطلوبين والمهام الفرعية.
3. **استرجاع السياق (Context Retrieval):** كل Agent بيسحب السياق اللازم من Knowledge Graph — بيانات العميل، تاريخ المشروع، Brand Guidelines، معرفة سابقة ذات صلة (عبر بحث دلالي/vector search).
4. **التنفيذ (Execution):** الـ Agent بينتج المخرج (اقتراح، مسودة، تحليل) باستخدام أدواته المتخصصة.
5. **المراجعة (Supervision):** AI Supervisor يراجع المخرج مقابل البراند والسياسات، ويصنّفه آمن/حرج.
6. **القرار (Decision):**
   - آمن → يُنفذ وينشر حدث (event) للموديولات المعنية.
   - حرج → يتوقف عند بوابة موافقة بشرية، مع توضيح كامل لسبب الاقتراح والبيانات اللي بني عليها.
7. **التسجيل والتعلم (Logging & Learning):** كل قرار وكل موافقة/رفض بشري بيُسجّل — وبيصير جزء من الذاكرة (Knowledge Base) لتحسين قرارات الـ Agent المستقبلية لنفس النوع من المهام.

## التواصل بين الوكلاء

- **Event Bus مشترك:** الوكلاء ما بتتصل ببعضها مباشرة — بتنشر وتستهلك أحداث عبر نفس طبقة الأحداث اللي الموديولات (الجزء الثالث) بتستخدمها. هيك أي Agent جديد بيقدر "يسمع" لأحداث موجودة بدون تعديل على الوكلاء التانية.
- **بروتوكول تمرير المهام:** لما Agent يحتاج مخرج من Agent تاني (مثلاً Marketing Strategist محتاج تصميم من Design Agent)، الطلب بيمر عبر AI Orchestrator، مو اتصال مباشر بين الوكلاء — هيك التنسيق والتسجيل مركزي ومتتبّع بالكامل.

## الذاكرة المشتركة (Shared Memory)

كل الوكلاء بتشارك نفس طبقتين ذاكرة، بدل ما كل وكيل يبني ذاكرته الخاصة المعزولة:

1. **الذاكرة البنيوية (Structured Memory):** بيانات Knowledge Graph نفسها — عملاء، مشاريع، حملات، مالية (الجزء الخامس). أي Agent بيقدر يستعلم عنها مباشرة.
2. **الذاكرة الدلالية (Semantic Memory):** Knowledge Base مع embeddings — مقالات، قرارات سابقة، دروس مستفادة، محادثات مهمة موثقة. بتُستخدم للبحث "شو صار قبل هيك بموقف مشابه؟"

هالمشاركة هي اللي بتمنع تكرار الأخطاء وبتخلي كل Agent "يعرف" سياق الوكالة كامل، مو بس المهمة الحالية.

## اتخاذ القرار ومبدأ Human-in-the-Loop

مافي استثناء: أي إجراء مصنّف "حرج" من AI Supervisor **لازم** يمر ببوابة موافقة بشرية صريحة، بغض النظر عن مدى ثقة الـ Agent بقراره. هالقاعدة مبنية بمستوى النظام (enforced at the platform level)، مو قرار يقدر Agent يتجاوزه أو مطوّر يعطّله بسهولة بموديول واحد.

بوابة الموافقة بتعرض دايماً:
- شو الاقتراح بالضبط.
- مين الـ Agent اللي اقترحه.
- شو البيانات/السياق اللي بني عليه القرار.
- الأثر المتوقع (مثلاً: "هاد بيرسل فاتورة بقيمة X للعميل Y").

هيك الإنسان بيتخذ قرار مبني على معلومة كاملة، مو موافقة عمياء على "صندوق أسود".
