# الجزء السادس: بنية الواجهة وتجربة المستخدم

الهدف من هالجزء: تجربة استخدام **خفيفة وسريعة وسهلة**، تخلي الفريق يشعر إن كل معلومة بالنظام بترجع عليه بقيمة فعلية — مو واجهة مثقلة بميزات ما حدا بيستخدمها. المرجعية بالجودة: هب سبوت، مونداي، نوشن — بس مبنية لسياق وكالة تسويق تحديداً، مو أداة عامة.

## مبادئ التصميم الأساسية

1. **السرعة قبل كل شي (Speed as a Feature)** — أي صفحة لازم تفتح وتتفاعل بأقل زمن ممكن. الثقل البصري أو التقني بيقتل ثقة المستخدم بالنظام أسرع من أي باق تصميم.
2. **الكثافة المعلوماتية الذكية** — مو "أقل معلومات = أبسط". الهدف عرض المعلومة الصح بالمكان الصح، مو إخفاء كل شي وراء نقرات إضافية.
3. **AI حاضر بس مو مزعج** — الذكاء الاصطناعي متاح بكل مكان (عبر AI Command Center)، بس ما بيقاطع تدفق شغل المستخدم العادي. المستخدم يقدر يشتغل بدون AI بنفس السلاسة، ويستدعيه لما يحتاجه.
4. **اتساق كامل بنظام التصميم (Design System)** — نفس المكونات (components)، نفس الألوان، نفس سلوك التفاعل بكل موديول. المستخدم يتعلم النظام مرة وحدة، مو يتعلم كل موديول لحاله.

## البنية العامة للواجهة

```
┌───────────────────────────────────────────────────────────────┐
│  Top Bar: بحث عام / إشعارات / AI Command Center (اختصار سريع)    │
├──────────┬────────────────────────────────────────────────────┤
│          │                                                    │
│ Sidebar  │                  منطقة المحتوى الرئيسية               │
│          │        (Dashboard / صفحة موديول / تفاصيل كيان)        │
│  الموديولات│                                                    │
│  المفضلة  │                                                    │
│          │                                                    │
├──────────┴────────────────────────────────────────────────────┤
│         AI Command Center (Panel جانبي قابل للفتح/الإغلاق)        │
└───────────────────────────────────────────────────────────────┘
```

## الشريط الجانبي (Sidebar)

- منظم حسب الموديولات (الجزء الثالث)، بس مو كل الموديولات ظاهرة دايماً — المستخدم بيقدر يخصص ويثبت (pin) الموديولات اللي بيستخدمها كتير.
- بنية هرمية بسيطة: موديول → أقسام فرعية (مثلاً: المشاريع → نشطة، مكتملة، لوحة Kanban).
- مؤشرات حالة لحظية (badges) — عدد المهام المعلقة، الموافقات المنتظرة — بدون ما يحتاج المستخدم يفتح الموديول ليعرف إنه في شي بينتظره.
- قابل للطي (collapse) بالكامل لما المستخدم يحتاج مساحة أكبر للمحتوى.

## لوحة التحكم (Dashboard)

الصفحة الأولى اللي المستخدم بيشوفها، ومختلفة حسب الدور:

- **مدير الوكالة:** ربحية عامة، صحة الحسابات (Client Health)، حملات نشطة، تنبيهات مالية.
- **مدير حساب/مشروع:** مشاريعه النشطة، مواعيد تسليم قريبة، طلبات موافقة معلقة عليه.
- **فريق إبداعي:** مهامه، طلبات تصميم/فيديو من AI Studios بانتظار مراجعته.

كل widget بلوحة التحكم قابل للنقر مباشرة لمصدر البيانات (drill-down) — لوحة التحكم عرض ملخّص، مو نهاية الطريق.

## الصفحات (Pages) — نمط موحّد

كل موديول (عملاء، مشاريع، حملات...) بيتبع نفس النمط البصري:

1. **صفحة القائمة (List View):** جدول/كروت قابلة للفلترة والفرز، بحث فوري، وإجراءات جماعية (bulk actions).
2. **صفحة التفاصيل (Detail View):** معلومات الكيان + تبويبات (نشاط، مهام مرتبطة، ملفات، تعليقات) + سياق AI (اقتراحات ذات صلة بهاد الكيان تحديداً).
3. **نموذج الإنشاء/التعديل (Form):** بسيط، بحقول ذكية (auto-complete من كيانات موجودة، مو كتابة حرة لأي شي عنده علاقة بكيان تاني).

هالتوحيد يعني مطوّر جديد بيقدر يبني موديول جديد بسرعة لأنه بيتبع نمط معروف، ومستخدم بيتنقل بين الموديولات بدون ما يتعلم واجهة جديدة كل مرة.

## مركز قيادة الذكاء الاصطناعي (AI Command Center) — تجربة المستخدم

مو نافذة شات منفصلة بزاوية الشاشة — هو **panel جانبي** متاح من أي صفحة بالنظام، وبياخد بالحسبان وين المستخدم موجود حالياً (سياقي):

- لو المستخدم فاتح صفحة عميل معيّن وفتح الـ AI Command Center، الـ AI بيعرف تلقائياً إنه عن هاد العميل بدون ما يحتاج المستخدم يشرح من جديد.
- كل طلب من هون بيمر عبر AI Orchestrator (الجزء الرابع)، وبيظهر بوضوح: مين الـ Agent اللي رد، شو استند عليه، وهل الاقتراح "آمن" أو "بينتظر موافقتك".
- طلبات الموافقة المعلقة (Approval Requests) بتظهر كقائمة واضحة هون — مركز واحد لكل قرار AI بينتظر إنسان، مو مبعثر بإشعارات متفرقة.
- المحادثة موثقة ومرتبطة بالكيان (Client/Project/Campaign) اللي دارت حوله — قابلة للرجوع إليها لاحقاً كجزء من Knowledge Base.

## التقارير (Reports)

- **تقارير جاهزة** لكل موديول (أداء حملة، ربحية عميل، إنتاجية فريق) — تفتح بنقرة وحدة من صفحة التفاصيل ذات الصلة.
- **باني تقارير مرن (Report Builder)** للاحتياجات المخصصة — اختيار مقاييس (metrics) وأبعاد (dimensions) من أي موديول، مع دعم AI لتوليد تقرير من وصف نصي ("قارنلي ربحية العملاء التلاتة الكبار آخر ربع").
- كل تقرير قابل للجدولة والإرسال التلقائي (يعتمد على Automation Engine).

## التنقل والبحث العام (Navigation & Global Search)

- **بحث عام سريع (Command Palette, مثلاً بـ Cmd/Ctrl+K)** — يقدر يوصل لأي كيان بالنظام (عميل، مشروع، حملة، مقالة معرفة) بكتابة حرة، بدون ما يحتاج يعرف وين بالظبط.
- نتائج البحث مدعومة بالبحث الدلالي من Knowledge Graph (الجزء الخامس) — مو بس تطابق حرفي بالاسم.
- تنقل بالكيبورد بالكامل للمستخدمين المتقدمين (لا اعتماد إجباري على الماوس لأي إجراء أساسي).

## الأداء كمعيار تصميم

- **Optimistic UI** لكل إجراء بسيط (تعليق، تعديل حالة مهمة) — الواجهة بتستجيب فوراً، والتزامن مع السيرفر بيصير بالخلفية.
- **تحميل تدريجي (progressive loading)** للصفحات الثقيلة بالبيانات (لوحات تحكم، تقارير) — الهيكل يظهر فوراً، البيانات تتحمّل تباعاً.
- **لا انتظار على استجابة AI** — أي طلب AI بياخد وقت أطول بشكل طبيعي، فالواجهة دايماً بتوضح إنه الـ Agent شغال (حالة تحميل واضحة)، وبتسمح للمستخدم يكمل شغل تاني بالتوازي، مو يعلق بانتظار الرد.
